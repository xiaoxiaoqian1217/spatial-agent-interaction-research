# Paper

本目录用于保存**正式论文正文及其直接相关材料**。

## 约定

- 正式论文主文件：`thesis.docx`，只维护这一份 Word 文件，不另存修订版 docx。
- `thesis.md` 是正文修订工作稿，内容修订先在此处进行，便于查看 diff。
- 需要更新 Word 时，将 Markdown 中的修订同步到唯一主文件 `thesis.docx`，不另存其他论文 Word 文件。
- Word 被占用时，将修改保留在 `thesis.md`，记录待同步状态。
- 若 Word 端有直接改动（如导师批注合入），先核对 Markdown 中的待同步修改，再使用 `scripts/docx_to_md.py` 导入对齐，避免覆盖修订。
- 如学校或期刊提供模板，可将模板文件一并放在本目录。
- 不在此目录存放外部参考论文；外部论文统一放到 `literature/papers/`。
- 论文中的正式插图建议源文件保存在 `assets/figures/`，正文只引用最终版本。

## 为什么正文使用 Word

当前论文更适合以 `.docx` 作为主格式，便于导师批注、学校模板适配、目录与参考文献排版。仓库中的 Markdown 文件主要用于研究过程记录，不作为最终论文排版格式。

## 当前写作安排

采用题目《面向长时空间任务的人—智能体交互机制设计与实现》。现在开始写作，与文献核查、交互设计和原型实现同步迭代，不等待创新完全确定。

1. 先写引言及任务场景与需求：说明业务背景、用户任务、研究范围及待核查问题，贡献暂用工作表述。
2. 同步整理相关工作和低保真设计：优先比较空间交互方案，记录已有解决方案、需求假设和可能不足。
3. 原型逐步确定后补写机制与实现，区分拟议、已实现和模拟内容；技术贡献应服务于具体交互问题。
4. 实验后填写结果、讨论、最终贡献与摘要，不预写改善或显著性。
