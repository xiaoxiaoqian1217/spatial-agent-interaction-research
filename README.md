## 当前研究问题

本文关注用户表达目标后，由多个Agent解释要求、组织计划并持续执行的应用形态。执行过程中会产生理解确认、计划、工具结果、进度、变化、征询和结果等多类输出；输出来自多个智能体，聚合、归因与冲突呈现本身就是交互问题。

> 如何通过空间交互组织多个Agent执行过程中的多类输出，让用户理解发生了什么、在必要时参与调整，并确认结果符合要求？

传统界面也围绕用户需求设计，但常由用户将目标转换为具体操作。本文比较交互职责、信息组织和参与方式的变化，不预设Agent界面普遍优于传统界面。

G1支持过程理解，G2支持有效参与与结果确认。长时空间任务是应用与验证背景，空间交互是理解、参与与核查的主要手段：操作员远程监督空中、地面、四足无人平台班组，必要时调整目标与范围。设备控制、多智能体内部编排和事件协议为支撑能力；多源输出的聚合与归因是交互设计难点。

### `paper/` 与 `literature/papers/` 的区别

- `paper/`：**我们自己正在撰写的论文**。
- `literature/papers/`：**别人已经发表、用于阅读和引用的论文**。

## 论文大纲

2026-09-14 更新的[八节论文大纲](research/outline.md)，按“问题与目标—理论与任务分析—协同机制—原型—验证与讨论”组织。

场景分为系统应用、典型协作情境与具体业务案例。围绕目标委托、过程监督、Agent征询、用户主动调整、异常恢复、结果确认分析需求；道路封闭仅是验证案例。

三项机制为执行信息组织与呈现、协同介入、执行衔接与反馈。原五维改为跨机制设计准则，地图贯穿三项机制。

优先探索空间交互：围绕任务、设备、区域与路径，研究用户如何理解变化、表达调整和核查结果。空间对象与任务过程的联动、空间操作与语言表达的衔接是候选设计入口，尚未选定具体创新。交互机制和支撑交互的技术实现均可形成贡献，但需说明相对已有方案的差异及证据；不能由“单位尚未实现”或“感觉研究较少”推断新颖性。调整意图与落实关联保留为备选特色。
