# Spatial Agent Interaction Research

> 工作题目：面向长时空间任务的智能体协同交互机制设计与实现

本仓库用于管理论文研究全过程。**正式论文正文与研究过程材料分开管理**：论文正文放在 `paper/`，文献、研究框架、实验记录等使用 Markdown 等便于版本管理的格式。

## 当前研究问题

随着 Agent 从一次性问答转向长时运行、多阶段规划、工具调用以及可中断执行，用户面临的关键问题不再只是“能否获得正确结果”，而是：

> 用户能否在 Agent 执行过程中持续理解其任务目标、当前状态、行为依据和后续趋势，并在必要时进行有效干预？

业务背景为操作员远程监督空中、地面、四足三类无人平台班组，各有执行智能体，另有信息处理、态势分析、任务规划三类支撑智能体。长时空间指任务持续数小时以上、被控对象分布于地理空间；原型与人员研究的实际覆盖范围分别报告。

当前归纳为两个核心目标：

1. **建立正确的用户态势认知**：让用户知道 Agent 当前在做什么、进行到哪里、重要变化是什么、接下来可能发生什么。
2. **支持有效的人机协同控制**：让用户能准确参与取舍、调整任务，并判断要求是否真正落实。

### `paper/` 与 `literature/papers/` 的区别

- `paper/`：**我们自己正在撰写的论文**。
- `literature/papers/`：**别人已经发表、用于阅读和引用的论文**。

因此正式论文主文件只保留一处：`paper/thesis.docx`。

场景分为系统应用、典型协作情境与具体业务案例。围绕目标委托、过程监督、Agent征询、用户主动调整、异常恢复、结果确认分析需求；道路封闭仅是验证案例。

三项机制为执行信息组织与呈现、协同介入、执行衔接与反馈。原五维改为跨机制设计准则，地图贯穿三项机制。

优先打磨的候选创新是**调整意图与执行落实的关联反馈机制**：关联用户要求、计划变化和执行依据。设计见大纲4.2—4.3，针对性评价见6.6，Agent–Frontend分工见5.3。候选创新与效果仍需文献比较和验证支持。

## 研究原则

- 先明确研究问题，再选择实现技术。
- 区分“系统工程能力”和“论文研究贡献”。
- 每项交互机制都应对应明确的用户问题。
- 论文结论尽量由文献、实验、专家评审或其他可复核证据支撑。
