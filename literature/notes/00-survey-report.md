# 文献调研报告：设备异常后接替决策中的态势理解与调整影响

日期：2026-09-13。依据 `research/literature-handoff.md` 第 6–8 节执行。本报告是文献调研结果，不是创新论证；结论区分"已有方法已解决""业务事实仍待核实""可能存在不足但证据不够"。

## 1. 检索范围与方法

- 检索日期：2026-09-13；工具：Kimi 网络检索与全文抓取。
- 查询词（按交接文档第 6 节给出的方向组合执行）：
  - human supervisory control of multiple robots situation awareness task intervention survey
  - multi-robot task reassignment human operator communication failure recovery
  - mixed-initiative replanning plan repair human operator understanding impact
  - explainable AI planning plan explanation human user study alternatives comparison
  - teleoperation communication latency stale data display last known position uncertainty
  - "what-if" decision support operator schedule replanning unmanned vehicles Cummings OPS-USERS
  - situation awareness human interaction with multiple robots Endsley measuring SA
  - communication loss UAV ground control station link lost display degraded information
  - Chakraborti plan explanation model reconciliation；Honig Oron-Gilad failure review
- 筛选理由：优先综述、有人因实验的原始论文、有直接系统原型的论文；算法类重分配文献仅保留代表性条目用于"基线"判断；博客/厂商材料仅作工程实践旁证并单独标注。
- 覆盖限制（重要）：
  - 未检索 ACM/IEEE 全文库的系统性综述流程，不是系统综述；可能遗漏未开放获取的近作。
  - 未专门展开：军事 C2 指挥系统文献（多为非公开）、空管/过程工业的值班员接替研究、中文文献（仅命中一篇多无人机故障重规划算法，无交互内容）。

## 3. 三类区分

### 3.1 已有方法已解决（在明确条件下）

1. **失联检测与单机安全行为**：心跳/看门狗检测、lost-link 预定行为（悬停/盘旋/返航/着陆）是成熟工程规范（NPS 检查单逐条覆盖识别、时序、备份链路）。操作员"发现异常"不依赖自己盯图。
2. **失败后的自动接替**：当故障可检测、任务可完整描述、候选资源已知时，按距离/负载/截止时间自动重分配是成熟算法问题（MRPF、Haider、Bolarinwa；CBBA 局部修复甚至无需操作员）。商业工作站已有"任务转交"能力。
3. **安全暂停与对话恢复**：检测到故障即暂停任务树、对话决定恢复方式、恢复后继续，已有架构实现（Blankenburg 2020）。与交接文档第 5 节"先安全暂停再修改"的修正一致。
4. **方案比较工具**：调度方案的高层指标比较与 what-if 反事实查询已有系统与实测（SCT）；计划差异的形式化呈现（existing/removed/added/diffcost）已有原型（XAIP-as-Service）。
5. **介入触发**：机器按自信度求助 + 人按 SA 介入的双向框架已有命名与验证（JISA）。

### 3.2 业务事实仍待核实（文献无法代替）

1. 现有系统是否有任何自动接替/降级逻辑、有无成文接替程序（SOP）——若有，"逐台人工比较"的困难可能主要是配置/流程问题而非研究问题。
2. 失联恢复后设备是否补报期间进度（回执语义）——决定"未知范围"是持续存在还是短暂窗口。
3. 设备数量、能力异构程度、任务时限与错过后果——决定简单排序是否足够（OPS-USERS 经验：资源不饱和时比较工具几乎无人用）。
4. 操作员实际操作顺序、耗时与差错——交接文档已列为未获得。

### 3.3 可能存在不足但证据不够（不能写成研究空白）

1. **操作员面向的"未知语义"表达**：所查文献中，失联/陈旧数据主要按工程路线处理（看门狗、预测补偿、lost-link 行为）；面向操作员把任务状态区分为"已核实完成 / 截至 t 的最后报告 / 自此未知"并标注依据与数据时间的界面研究，本轮未见直接证据。但检索未覆盖军事 C2 与非公开系统，且"没搜到"不构成空白证明。
2. **接替决策的局部影响解释**：SCT 比较的是全局调度指标，XAIP 比较的是 PDDL 计划，均未在"失联接替"情境、以真实操作员、在长时任务上验证局部调整影响（对接替者原任务的波及）的解释机制。属"相邻证据存在、直接证据缺失"。
3. **长时与真实操作员证据普遍薄弱**：几乎所有实验为短时仿真、学生受试；室外飞行仅 1 名专家 22 分钟任务。这不是本项目的机会点本身，但意味着任何界面结论都需要自己收集长时/实操证据。

## 4. 候选研究问题（最多收敛至两个，附否定条件）

### RQ-A：失联后任务状态的"已知/未知"语义表达对接替决策的影响

- 依据：用户确认失联后完成情况未知带来判断困难（业务待核实）；Coldwell 2026 显示任务结果类状态（L2）判断显著弱于直接状态（L1），漏报型任务失败被误判为正常；Senaratne 2025 提供实际与所需 SA 脱节的类型学。
- 最近相关工作：Roldán 2017（预测成分显示，效果不稳——直接警示）；TeleXR（预测补偿路线）；工程看门狗（只标新鲜度，不标任务语义）。
- 可能差异：不显示"预测状态"，而显示"证据状态"——每条任务步骤标注依据（回执/推断/未知）与数据时间，把未知本身作为一等信息。与预测显示路线形成对照。
- 简单替代办法：现有状态标签 + 失联时间戳（一行文字）。实验必须以此为基线之一，证明额外语义有增量价值。
- 否定条件：若核实发现失联恢复后总会补报进度、或失联窗口极短，未知语义无实际决策价值，则放弃。
- 可行验证：仿真接替场景中操纵状态表达（标签 vs 标签+时间 vs 依据+未知范围），SAGAT 式探针测已知/未知辨别，接替决策正确率与耗时；先短时仿真，再争取真实操作员。

### RQ-B：接替候选的比较与影响说明（相对逐台查看与简单排序）

- 依据：用户确认逐台查看位置/任务/状态自行比较；OPS-USERS 证据显示黑箱分配引发不信任（53% 想手动指派）、而 what-if 工具在低约束时几乎闲置；自动重分配文献完全绕开人。
- 最近相关工作：SCT what-if（最近基线）；XAIP-as-Service 计划差异四元组（机制先例）；Chakraborti 模型调和（解释质量框架）。
- 可能差异：比较单位从"全局调度方案"收窄为"局部接替决策"——候选设备的并排对比 + 对各自原任务的波及 + 推荐依据，并显式区分算法建议与人决断。若与 SCT/XAIP 差异仅停留在场景迁移，则应降级为应用研究并明说。
- 简单替代办法：按能力/距离排序的候选列表（一屏表格）。这是必须击败的基线；OPS-USERS 经验预示在资源不饱和、候选少时排序可能已足够。
- 否定条件：候选设备常年 ≤3 台或能力同质化，或业务确认可上自动调度器，则该问题不成立。
- 可行验证：三臂对比（逐台查看现状 / 排序列表 / 比较+影响说明），操纵候选数量与资源饱和度，测决策质量、耗时、信任校准；归因检查须把界面收益与算法收益分开（用同一推荐算法驱动后两臂）。

**明确不收敛为独立研究问题的方向**：关联反馈/落实追踪（保留为 RQ-A/B 内的支撑机制）；LLM Agent 调试类比（仅机制借鉴）；通用"长时监督态势理解"（过大，且 Chen 2010 已系统综述）。

## 5. 下一轮需向用户核实的问题（仅列新信息）

1. 失联或异常后，系统目前是否有任何自动接替、降级或 SOP 程序？还是完全依赖操作员人工安排？
2. 设备恢复通信后，是否会补报失联期间的执行进度？操作员看到的"已完成"依据是什么（回执/推断/人工标记）？
3. 典型在管设备数量、能力差异程度（能否互相替代）、接替的距离/时间成本量级？
4. 任务是否有明确时限与错过后果？是否有接替延误或重复执行的真实记录（哪怕是轶事）？
5. 能否提供现有界面截图或一段真实操作日志（脱敏），用于还原第 3 节的案例链？

## 6. 对论文主线的收敛建议

建议把主线收窄为：**设备失联/异常后的接替决策支持**，以 RQ-A（未知语义）为主、RQ-B（方案比较）为从，两者共用同一实验平台与基线。"上级新增区域"保留为第二类评估场景，用于检验机制的可迁移性而非独立贡献。收敛前提：第 5 节问题 1–3 的回答不能证伪需求（尤其问题 1：若已有自动接替，整条线需要重议）。在核实完成前，论文任何位置不应出现"首次提出""尚无人研究"类表述；Chen 2012、OPS-USERS、XAIP 三个先例必须在相关工作中正面处理。

## 7. 补充讨论（2026-09-13 第二轮）："学术上不新，是否等于军工领域不新"

用户质疑：不新未必代表军工领域不新。补充中文军事/指挥控制来源检索后，结论如下：

1. **先例本身就出自军事研究，"领域转换"不能用来恢复机制新颖性。** RoboLeader 是美国陆军研究实验室（ARL）项目；OPS-USERS/Cummings 多 UAV 调度由军方资助；NPS lost-link 检查单是军用无人机靶场安全审查文件；STANAG 4586 地面站标准是北约互操作规范；公开报道中 Lattice（安杜里尔）、L3Harris"无形"系统等均把"节点失联后自动接替/动态重规划、单人监督数十台"作为已交付能力宣传。公开的军事工程话语里，这些能力不是前沿而是标配。
2. **真正不可知的是国内具体型号与本单位系统的现状**——这无法通过公开文献证实或证伪，只能靠第 5 节核实问题。"军工领域新不新"因此不是一个文献问题，而是一个现状核实问题。
3. **中文公开期刊**（2026-09-13 第三轮补充检索，详见 `zh-domestic-literature.md`）：算法侧国内同样拥挤且直接覆盖接替——《指挥与控制学报》2021 无人作战 C2 专题含《基于任务接力的多无人机协同目标分配方法》，《控制与决策》2022 有《面向突发故障的分布式多无人机任务重规划方法》，张安团队（西工大）长期产出任务重分配与人机功能分配工作；综述侧辛斌等（电光与控制 2024）、张宏宏等（航空学报 2023）已将"人在回路/混合增强智能"列为方向。人因界面侧有熊端琴等 2022 地面站工效评估、2006 年西工大 30 名现役战士的控制站 SA 实验，以及选题结构接近的学位论文《人在回路的 UUV 指控任务规划方法研究》（2021，待精读）。与本项目直接对应的"失联接替决策界面支持"中英文均未见，图景一致，但仍不构成空白证明（CNKI 未系统检索、军工内刊未覆盖）。
4. **对论文策略的含义**：若贡献定位为"机制首创"，军事领域与国内文献都不是避风港（先例即军事人因文献与国内 C2 期刊论文，评审专家大概率熟悉 Cummings/ARL 与张安、辛斌等团队工作）；若定位为"面向具体业务系统的应用与实证创新"——创新点落在业务语义建模（已知/未知/依据）、接替决策支持机制的适配与实测验证——则成立且不依赖"没人做过"，只依赖"本单位系统确实缺失 + 验证有效"。建议采用后者，并在绪论中明说贡献类型。
5. 本报告第 3.3 节的"疑似缺口"表述维持不变：缺口判断的依据是机制层面未见直接证据，而不是"民用有、军用没有"或"国外有、国内没有"的假设。另：RQ-A 设计须增补 FAA《Human Factors Design Guidelines for Multifunction Displays》的"显示不确定性"专节为先例（图形显式符号优于文本/颜色；不确定性影响安全时应显示）。
