# 执行中修改任务：交互困难的一手研究证据

核对日期：2026-09-15。
这份笔记用于发现候选问题，不是本项目用户调研结果，也不是动态界面或交互 Agent 的创新证明。
下文区分原研究的发现与我们对“执行中新增巡查区域”的推演。

## 1. 空间位置用语言说清楚，确实可能费劲

来源：Sharon Oviatt，Multimodal Interfaces for Dynamic Interactive Maps，CHI 1996。
[ACM 原文正文](https://chi1996.acm.org/proceedings/papers/Oviatt/slo_txt1.html)，重点见 Method、Results 和 Discussion。

- 研究场景：18 人在由人模拟系统理解的地图环境中完成选房和地图更新，比较语音、笔输入与两者结合。
- 原研究发现：结合笔和语音比只用语音更快、任务关键内容错误更少；错误包括方向说反，以及把距离以内说成以外。
- 有限迁移：新增区域时，值得检查用户是否需要把本来可以直接指明的边界，费力翻译成文字，以及语言与选区是否指向同一对象。
- 不支持的结论：它没有测试现代 LLM、键盘聊天或我们的巡查任务，不能证明动态生成界面优于固定的地图加输入框。
- 反例提醒：参与者更喜欢参照信息较完整的地图；界面越精简、越自由，并不自动越好用。

## 2. 让用户能改，不等于修改真的生效

来源：Mozannar 等，Magentic-UI: Towards Human-in-the-loop Agentic Systems，2025 技术报告。
[作者论文 v1](https://arxiv.org/html/2507.22358v1)，重点见 7.4 Qualitative User Study。

- 研究场景：12 人进行一小时浏览器任务研究，包括订餐、整理食谱和票价计算。
- 原研究发现：部分用户修改计划后，系统未采纳修改；用户希望更清楚地看见计划变化，也希望修改已完成步骤后从那里重跑。
- 有限迁移：新增区域后，值得检查用户能否区别“系统收到要求”“计划已更新”和“执行已按新要求进行”；需要后台提供对应状态，界面不能自行宣称生效。
- 不支持的结论：这是小规模质性研究，不能估计本项目故障率，也不能把模型执行错误都归因于界面。
- 反例提醒：用户刚要求修改就再被要求批准，有时被认为多余；延迟和冗长说明本身也是负担。

## 3. 修改后仍然有用的工作，不该轻易丢掉

来源：Feng 等，Cocoa: Co-Planning and Co-Execution with AI Agents，CHI 2026。
[作者发布的论文](https://kevinpjk.github.io/assets/pdf/cocoa_chi_2026.pdf)，重点见第 5-8 节；这里使用 2026 版，区别于只有实验室研究的早期预印本。

- 研究场景：科研文档中的共同规划与执行，包含 16 人实验室研究，以及 7 人、7 天的部署。
- 原研究发现：与同一后台 Agent 的聊天基线相比，交互计划改善了用户引导 Agent 的体验，未牺牲易用性；重规划时，有参与者仍想保留旧步骤及输出作为参考。
- 有限迁移：值得检查新增区域或修改要求时，原选区、已填参数与已有执行结果哪些仍有效，用户能否保留和复用它们。
- 不支持的结论：科研文档不等于运行中的空间任务；本文没有证明保留巡查业务约束的具体机制。
- 反例提醒：作者指出开放探索可能适合较短计划，更多控制也可能增加负担，不应强迫所有任务走完整计划。

## 4. 纠错、记住上下文和反馈后果，已有通用设计依据

来源：Amershi 等，Guidelines for Human-AI Interaction，CHI 2019。
[作者论文](https://www.microsoft.com/en-us/research/wp-content/uploads/2019/01/Guidelines-for-Human-AI-Interaction-camera-ready.pdf)，重点见表 1 和第 5 节。

- 研究场景：49 名设计从业者针对 20 个 AI 产品检查指南的适用性与清晰度，不是巡查任务的效果实验。
- 作者建议：支持方便纠正、目标不明确时澄清、记住近期交互、说明操作后果，并谨慎改变系统行为。
- 有限迁移：这些建议可以变成走查问题，例如用户能否只修正错的一处，是否被迫重述已有信息，以及修改后发生了什么是否清楚。
- 不支持的结论：遵守指南不等于产生新颖贡献；不能据此认定必须增加交互 Agent 或自动识别用户认知需求。

## 对本项目最值得继续检查的三个问题

以下是基于文献和场景的推演，尚未证明在本项目中反复出现。

1. “我说的这里，和系统理解的这里，是不是同一个范围？”
2. “我只改这一处，原来不要改的要求和已经做过的工作还在不在？”
3. “我已经提出修改，现在到底改到了哪一步？”

其中第二项的“原业务约束被意外改变”目前缺少直接的同领域实证证据，不能写成文献已证明的事实。
三项问题都可能通过合理的固定界面和规则解决，现有证据不能直接推出规则工作流不够用。
比较方案应使用功能完整的地图、任务编辑与反馈界面，不能仅选一个缺少基本纠错能力的聊天框作为对手。
