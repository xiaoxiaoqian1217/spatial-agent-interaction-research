# 文献调研交接：动态介入时的态势理解与调整影响

日期：2026-09-13。本文记录本轮用户讨论，是当前调研入口；不是已完成的需求研究或创新论证。

> **2026-09-13 更新：** 调研已完成（见 `literature/notes/00-survey-report.md`）。用户随后确认：接替现由设备群（多智能体）自动完成，本文第 2、3 节"逐台人工比较、自动推荐是期望新增"的描述属于老设计，已过时；操作员保留否决/改派权，接替不合适可能发生。当前整体论题与机制以 [research-question.md](research-question.md) 的整体定位确认版为准；本文以下调研任务为历史范围，自主接替不再作为全文主线。

## 1. 接手任务

先阅读本文件，再查阅相关论文及已有系统。沿“业务场景 → 具体困难 → 现有处理办法 → 相关研究及不足 → 研究问题 → 方法与验证”的顺序工作。寻找反证及已有成熟解决方案，不为预设创新寻找支持。

当前方向：长时任务执行过程中，操作员需要介入时，如何理解当前任务情况，并看清调整对设备、任务和后续安排的影响？

长时背景不自动证明理解困难、疲劳或脱离回路。当前更具体的切入点是设备异常后的接替决策；保留上级新增区域这一另一类场景，不将全文提前缩成失联处理。

## 2. 用户口述确认的业务情况

以下来源是本次用户对话，尚未通过日志、现场观察或独立访谈验证；不写成已开展的实证研究。

- 两类介入触发：上级新增侦察区域；设备失联或异常，原任务可能无法完成。
- 设备失联时，操作员看到地图设备图标不再移动，同时收到失联提示。图标停止更新不证明实体设备停止运动。
- 用户推测通常先查看任务进度，再看设备详情；操作顺序仍待核实。
- 任务进度有步骤及“已完成、执行中、未开始”等状态；用户表示可能没有百分比。
- 操作员有权直接安排另一台设备接替。
- 目前选择接替设备需要逐台查看位置、当前任务和设备状态，自己比较选择。
- 用户确认需要跨处查找、拼合信息，也认可失联后完成情况未知给等待或接替判断带来的困难。
- 自动推荐可接替设备是用户希望增加的设计，明确不是已确认的现有功能。

未获得：实际设备数量、任务时限、操作耗时、错误发生率、具体事故、现有界面截图、回执语义、真实执行日志。

## 3. 当前还原的案例与判断任务

收到失联提示 → 查看最后已知任务步骤 → 查看设备详情 → 逐台比较其他设备 → 判断是否接替并选择设备 → 安排接替。

后续下发、确认和恢复流程尚未核实，不补写成业务事实。

操作员需要判断：
1. 待接替范围：哪些已确认完成，哪些未知，哪些需要继续？
2. 接替对象：谁具有所需能力，当前位置、任务和设备状态是否允许接替？
3. 调整影响：接替会怎样影响该设备的原任务及相关安排？

失联不等于任务失败或停止。最后报告“执行中/未开始”不是失联后的实时真值；“已完成”也需核实其依据。过去发生的动作不能被计划修改撤销。等待可能延误，接替可能重复并占用资源：这些是待核实的决策后果，不是已观测的事故。

## 4. 候选设计与待检验问题

候选设计：围绕接替决策汇集必要信息，区分已知事实与未知范围，提供可比较方案，说明推荐依据、原任务影响和取舍；必要时追踪确认后的落实。

候选评价问题：相比现有逐台查看方式，这种组织与解释是否帮助操作员更快、更准确地选择接替方案，并识别不确定性？收益、额外负担和推荐误导都需要检验。

规划算法生成方案与交互机制帮助人判断方案是不同贡献。不能把更强后台算法带来的收益归因于界面；推荐、摘要、状态标签、地图或信息聚合本身均不自动构成创新。

## 5. 已修正的旧定位

早期曾把“用户编辑时设备继续运行，提交时状态过时”作为核心。用户指出可以先安全暂停再修改，因此不再以不停机编辑为必要前提。暂停不能替代后续重规划、影响判断和落实核查，但也不能据此直接认定这些需求有新颖性。

旧文档优先强调“调整意图与执行落实的关联反馈”。现在将其保留为候选支撑机制，核心贡献尚未确定，不能继续当作已选定创新。

状态改变实质影响用户意图时需解释并遵循业务权限；不能擅自把“禁入”改成“立即退出”。执行中不等于完成，发送成功不等于执行落实。

## 6. 文献调研重点

围绕以下问题搜索并阅读全文，优先原始论文、正式出版记录和系统官方资料：

- 多机器人监督中，用户怎样汇集任务进度、平台状态、空间信息以作出介入决定？
- 失联、异常、部分可观测条件下，已有界面怎样表达不确定性、数据时间及信息来源？
- 任务重分配/计划修复方法怎样支持操作员理解局部调整对其他任务的影响？
- 是否已有候选设备比较、推荐理由、反事实方案或计划差异呈现？有效性如何验证？
- 哪些困难可由常规排序、汇总面板、安全暂停、成熟调度器解决？在哪些条件下已足够？
- 研究面向真实操作员还是开发者？是否覆盖实体多设备、实际长时任务和异常接替？不要由短时实验推断长期效果。

可用检索词组合（不要求局限于 LLM Agent）：human-robot supervisory control; multi-robot task reassignment; mixed-initiative replanning; plan repair; situation awareness; decision support; explanation of planning; communication loss; uncertainty visualization; task allocation explanation。
