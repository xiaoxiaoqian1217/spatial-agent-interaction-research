# 研究框架

## 总体结构

当前采用“总问题 → 核心目标 → 设计维度”的分层方式组织研究问题。

```text
长时空间任务中的智能体人机协作
│
├─ 1. 建立正确的用户态势认知
│  ├─ 注意力选择：用户需要知道什么？
│  ├─ 状态可理解性：智能体现在在做什么？
│  ├─ 连续性：当前事件如何与前后过程及任务目标建立联系？
│  └─ 可预期性：接下来可能发生什么？
│
└─ 2. 支持有效的人机协同控制
   └─ 可介入性：用户何时、以什么方式介入？
```

## 五个设计维度

| 维度 | 核心问题 | 当前含义 |
|---|---|---|
| 注意力选择 | 用户需要知道什么？ | 从大量执行事件中筛选真正值得用户关注的信息 |
| 状态可理解性 | Agent 现在在做什么？ | 将内部执行状态转换成用户能理解的任务状态 |
| 连续性 | 当前事件如何与前后过程及任务建立联系？ | 保持任务目标、阶段、历史变化之间的上下文连续 |
| 可预期性 | 接下来会发生什么？ | 帮助用户形成对后续步骤、风险与等待时间的合理预期 |
| 可介入性 | 用户何时、如何介入？ | 在关键节点支持确认、纠偏、调整、暂停或中止 |

## 使用方式

这个框架当前是研究假设和分析框架，而不是已经被证明的最终模型。

后续每个维度都需要回答三件事：

1. **用户问题是什么**：缺少该能力时，用户会遇到什么具体困难？
2. **交互机制是什么**：系统通过什么界面或交互方式解决？
3. **如何验证**：通过专家评审、任务实验或其他证据验证是否有效？

## 与“金字塔原理”的关系

这里借用的是分层组织思想，而不是把金字塔原理本身作为论文理论模型：

```text
总研究问题
    ↓
两个核心研究目标
    ↓
五个可研究、可设计、可验证的交互维度
    ↓
具体交互机制与实验
```

因此，金字塔原理主要用于帮助研究结构保持 MECE 和层级清晰，论文真正需要建立和验证的是“态势感知—协同控制”的交互机制框架。
