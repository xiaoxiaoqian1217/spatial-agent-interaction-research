# 研究问题

## 已确认研究题目

**面向长时空间任务的智能体交互机制研究——用户态势感知与动态干预**

> 2026-09-09 已确认研究题目及[八节论文大纲](outline.md)。后续投稿措辞可根据研究结果与投稿要求调整。

## 核心问题

随着智能体从一次性问答转向长时运行、多阶段规划、工具调用以及可中断执行，用户面对的问题不再只是“智能体最终是否给出正确结果”，还包括：

> **在智能体持续执行任务的过程中，用户如何形成对任务态势的正确理解，并在必要时进行及时、有效且低负担的干预？**

## 两个核心研究目标

### 1. 建立正确的用户态势认知

研究用户在长时任务执行过程中需要感知哪些信息，以及这些信息应该如何组织与呈现，使用户能够理解：

- 当前任务目标是什么；
- 智能体当前正在做什么；
- 当前执行处于什么状态；
- 哪些变化值得关注；
- 变化对原目标或计划意味着什么；
- 接下来可能发生什么；
- 离开执行过程后返回时，期间发生了哪些关键变化。

### 2. 支持有效的人机协同控制

研究用户在什么情况下需要介入，以及系统应如何提供适当的干预方式，使用户能够：

- 确认关键决策；
- 调整目标或约束；
- 对执行过程进行纠偏；
- 暂停、中止或恢复任务；
- 理解修改从哪里开始生效、影响哪些未完成任务；
- 正确识别修改已生效、部分生效、被拒绝或未生效。

## 两个可验证评价问题

为避免研究目标停留在“界面提供了什么”，论文将两个目标进一步转化为可由实验回答的问题：

### EQ1：用户态势感知

> **相比基础交互，本文机制能否帮助用户更准确地理解 Agent 当前执行状态、关键变化及其后续影响？**

主要通过预设任务事实和实际执行状态判断用户回答是否正确，重点覆盖计划变化、环境变化以及用户离开后返回等情境。

### EQ2：人机协同控制

> **本文机制能否帮助用户正确实施任务调整，并准确判断调整是否真正生效？**

主要考察干预对象与范围是否正确、实际执行是否符合调整要求，以及用户能否正确识别生效、部分生效、拒绝或失败结果。

认知负荷、控制感、满意度和访谈用于辅助解释，不替代上述客观任务证据。

## 长时空间任务的操作化边界

本文不将“运行时间更长”作为长时任务的充分定义。研究关注的是执行期间出现状态演化、上下文累积和用户重新介入问题的空间任务。

代表性任务通常具有以下特征：

- 执行跨越多个阶段；
- 任务或环境状态持续变化；
- 计划可能在执行过程中调整；
- 用户可能离开执行回路后重新返回；
- 任务对象之间具有持续的空间关系；
- 执行过程中存在用户介入机会。

“空间”也不仅指界面包含地图，而是任务目标、计划步骤、设备、路线、区域等对象与执行状态之间存在持续的空间关系，这种关系会影响用户如何理解当前情况和确定干预对象。

## Agent–Frontend 协同边界在研究中的位置

地图前端在 Agent 执行过程中可能承担三种不同职责：

1. **前端规则：** 当已有业务结果足以确定地图行为时，前端按确定性规则完成呈现。
2. **共享前端状态 / 上下文：** 当 Agent 的任务判断依赖当前选中对象、编辑状态、空间范围等交互上下文时，仅共享必要状态。
3. **Frontend Tool / 前端交互能力：** 当 Agent 的任务执行需要当前前端交互环境完成一次能力时，由 Agent 主动请求前端执行，并在后续任务需要时取得执行结果。

该边界用于解释前端何时只是呈现层、何时进入 Agent 的任务执行过程。它是交互机制中的设计问题，而不是独立的“Frontend Tool 技术研究”。是否使用 CopilotKit、AG-UI 或其他具体实现方式不构成论文贡献本身。

## 当前研究边界

### 研究重点

- 长时、多阶段、可持续执行的智能体任务；
- 带有持续空间状态和地图交互特征的任务场景；
- 智能体执行过程中的信息组织、地图关联、上下文恢复与用户介入机制；
- 用户态势感知与人机协同控制之间的关系；
- Agent 与地图前端之间与任务执行直接相关的状态、能力和确定性响应边界。

### 当前不作为核心研究问题

- 大模型本身的规划算法精度；
- 通用多智能体调度算法；
- 地图路径规划算法性能；
- AG-UI、CopilotKit 等具体协议或框架的性能比较；
- Frontend Tool 相对于规则的普遍优劣证明；
- 通用 Agent–Frontend 通信架构设计。

这些技术可以用于原型实现，但不直接等同于论文贡献。

## 待验证的问题

1. 长时智能体任务中，哪些执行信息真正影响用户的态势认知？
2. 如何组织执行状态，使用户既能理解过程，又不会被大量中间信息淹没？
3. 用户离开执行过程后返回时，哪些变化信息最有助于恢复上下文？
4. 哪些任务情境需要提供用户介入能力，干预对象和范围应该如何表达？
5. 用户能否正确区分修改请求、接受、部分生效、拒绝和实际执行结果？
6. 任务与空间对象的持续关联是否有助于用户理解变化并确定干预对象？
7. 在具体任务中，前端何时适合采用确定性响应、共享交互上下文或 Agent 发起的前端能力调用？该问题用于分析设计取舍，不预设普遍性优劣结论。
